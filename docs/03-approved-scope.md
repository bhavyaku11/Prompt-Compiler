# Approved Scope

## P0 — Initial Product

### Core Compiler
- Rough requirement input
- Requirement extraction
- Intent detection
- Confirmed vs unknown information
- Safe-default handling
- Refined prompt generation
- Prompt validation
- Basic prompt critique

### Modes
- Quick Refine
- Optional Prompt Interview

### Templates
- Coding
- Debugging
- UI/UX changes
- College/academic work
- Documentation
- General software task

### Context
- Current project context
- Approved project decisions
- Conversation context
- Prompt history

### Local AI
- Ollama integration
- Qwen3 4B
- Provider abstraction

### API Foundation
- Health endpoint
- Compile endpoint
- Structured request/response schemas
- Error handling

## P1 — Later
- Screenshot understanding
- Handwritten sketch understanding
- Vision-model integration
- URL/webpage extraction
- File/document extraction
- More agent-specific formatting
- Persistent semantic memory
- Advanced prompt evaluation
- User feedback analytics

## P2 — Future
- Model fine-tuning based on collected feedback
- Multiple local model selection
- Optional cloud providers
- Team/shared project knowledge
- Advanced autonomous prompt planning
- Full macOS installer and first-run model management

## Scope Enforcement
If a requested task is outside the current approved phase, the AI must identify it as later scope and ask for approval before implementing it.

Do not implement P1/P2 functionality during a P0 task merely because it appears convenient.
